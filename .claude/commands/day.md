description: Ежедневный цикл проекта — идеи, формализация, документы, проверки
---

Выполни ежедневный цикл проекта. Правила — в `AGENTS.md`; этот файл задаёт порядок
шагов и границы одного дня. Аргумент команды, если он есть, — пожелание пользователя на
сегодня (узел, идея, ограничение по времени): $ARGUMENTS

Цикл идёт без вопросов к пользователю. Решения, которые принимает только он, собираются
в конце отчёта. Коммитов цикл не делает. Задачи в Aristotle он отправляет сам: запуск
`/day` — прямой запрос пользователя на отправку по разделу 3.

## 1. Состояние

1. `git status --short` и `git log -3 --oneline`: что изменилось со вчера.
2. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check.ps1`. Если проверка
   не проходит, день начинается с починки; новых целей до зелёной сборки не бери.
3. Прочитай открытые узлы в `blueprint.md`, раздел «Задачи Aristotle» там же и
   `ideas.md` целиком.
4. Ключ Aristotle берётся из переменной `ARISTOTLE_API_KEY`; если в оболочке её нет,
   прочитай пользовательскую:
   `[Environment]::GetEnvironmentVariable('ARISTOTLE_API_KEY','User')`. В файлы и в
   отчёт ключ не попадает. Без ключа шаги с Aristotle пропускаются, в отчёте об этом
   одна строка.
5. Для каждой строки «ответ не получен» из «Задач Aristotle»:
   `aristotle tasks <project-id>`. Готовый ответ скачай в `output/` и прими по разделу
   «Aristotle» из `AGENTS.md` (сверка заголовков с заготовкой, `sorry`, `axiom`,
   локальная сборка, `#print axioms`). `OUT_OF_BUDGET` с частичным результатом —
   `aristotle continue <project-id> "<что осталось>"`.

## 2. Идеи

Для каждого открытого узла из `blueprint.md` и каждого пункта «Не решено» из
`question.md`:

1. Перечитай записи `ideas.md` по этому узлу. Отвергнутую идею заново не предлагай;
   новая идея должна отличаться от неё гипотезой или методом.
2. Предложи от одной до трёх идей. Идея — точная формулировка (гипотезы, вывод, область
   определения), набросок доказательства по шагам и названные опоры: записи C1–C16,
   теоремы Lean, карточки из `sources/results.md`.
3. Проверь идею до записи: контрольные случаи из `question.md` ($a=0$, $a=1/2$,
   $a=x/2$), примеры C11 и C12, при необходимости расчёт в SymPy. Идея, которой
   противоречит доказанная теорема, записывается как отвергнутая вместе с причиной.
4. Запиши идею в `ideas.md` со статусом и следующим шагом. Статусы источника те же, что
   в `AGENTS.md`: непроверенный источник, собственный расчёт, цель исследования, лемма,
   доказанная в Lean.

Идея, требующая статьи, которой нет в `sources/`: найди первичный источник, добавь его
по правилам `sources/README.md`, пересобери каталог. Без полного текста источник остаётся
непроверенным.

## 3. Задача для Aristotle

Отправка идёт до локальной работы, чтобы сервис считал, пока цикл занят своей целью.
Сервис ведёт один проект: если вчерашний ещё `IN_PROGRESS` или `QUEUED`, новую задачу
сегодня не отправляй.

1. Выбери утверждение, которое не совпадает с целью дня из раздела 4: самое трудоёмкое
   из тех, у которых есть точная формулировка и бумажный набросок. Порядок: открытый
   узел из `blueprint.md`; лемма, на которой вчера остановилась локальная формализация;
   идея из `ideas.md` с проверенным наброском.
2. Утверждение без доказательства на бумаге, которое может оказаться неверным,
   отправляй только в форме «докажи или опровергни» и так и помечай в `ideas.md`.
   Цели без точной формулировки не отправляются.
3. Собери пакет `output/aristotle-<имя>/` по образцу `output/aristotle-open-nodes/`:
   весь проект, заготовка с `sorry` в новом модуле, `prompt.md` на английском с
   формулировкой, опорами в проекте и наброском доказательства. В библиотеку `Involution/`
   заготовка не попадает.
4. Проверь заготовку: `lake env lean output/aristotle-<имя>/Involution/<Модуль>.lean`
   даёт только предупреждения о `sorry`.
5. Отправь: `aristotle submit "<текст prompt.md>" --project-dir output/aristotle-<имя>`,
   лог — в `output/aristotle-<имя>-submit.log`, квитанция —
   `output/aristotle-<имя>-receipt.json`.
6. Запиши задачу в «Задачи Aristotle» `blueprint.md` со статусом «ответ не получен» и в
   `ideas.md` у соответствующей идеи.

В конце дня, перед отчётом, ещё раз вызови `aristotle tasks`: готовый ответ прими
сегодня, если на это хватает времени, иначе его заберёт завтрашний цикл.

## 4. Цель дня

Выбери одну цель локальной формализации. Порядок предпочтения:

1. принятый сегодня ответ Aristotle, который осталось перенести;
2. лемма, которая закрывает открытый узел или его часть;
3. идея из `ideas.md` с полным бумажным доказательством;
4. утверждение из `context.md`, у которого в Lean доказан только частный случай.

Цель годится, если её формулировка укладывается в существующие определения проекта или
требует не больше одного нового определения, а доказательство разбивается на леммы
длиной до ~50 строк. Новое определение, меняющее смысл постановки (как `MemIntervalH01`),
выносится в отчёт на подтверждение. Если подходящей цели нет, день уходит на идеи и
источники; в отчёте так и напиши.

## 5. Формализация

1. Запиши формулировку в `Scratch.lean` и добейся, чтобы она компилировалась с `sorry`.
   Имена Mathlib проверяй в `.lake/packages/mathlib/`, поиск — в `Search.lean`.
2. Докажи в новом или существующем модуле `Involution/`. В библиотеку `sorry` не
   попадает: недоказанная заготовка живёт в `Scratch.lean` или в `output/`.
3. `lake build`; для итоговой теоремы — `#print axioms` в `Scratch.lean`. Перед концом
   дня убери из `Scratch.lean` временные `sorry`.
4. Если лемма не поддаётся после трёх разных подходов, остановись и собери из неё пакет
   по разделу 3. Отправь его сразу, если сервис свободен; иначе запиши в `ideas.md`,
   что пакет готов, и его отправит завтрашний цикл.
5. Формулировку ради сборки не ослабляй. Если доказано более слабое утверждение, оно
   получает своё имя, а узел остаётся открытым.

## 6. Документы

Каждый факт живёт в одном файле, остальные ссылаются. Порядок правки:

1. `context.md` — новая или уточнённая запись C: условия, утверждение, доказательство,
   теоремы Lean, границы.
2. `blueprint.md` — строка узла, модуль в разделе «Модули», задачи Aristotle, счётчик
   открытых узлов в первом абзаце.
3. `ideas.md` — статус идей, с которыми сегодня работали.
4. `question.md` — раздел «Ответ на ДД.ММ.ГГГГ» с сегодняшней датой и список «Не
   решено». Постановку меняй только с явной пометкой об изменении условий.
5. `README.md` — таблица результатов и абзац под ней.
6. `sources/` — новые источники и карточки; `python sources/build_catalog.py`.
7. `review.tex` — статусы формализации и новые результаты; сборка PDF командой из
   `AGENTS.md`, без неразрешённых ссылок и `Overfull`.
8. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prepare-input.ps1`.

`exposition.tex` цикл не правит: его обновляет команда `/exposition`. Если сегодняшний
результат меняет ответ на вопрос статьи, напиши в отчёте, что её пора запустить.

В день без новых результатов правится только `ideas.md`. Дату в заголовке «Ответ на …»
из `question.md` меняй вместе с содержанием раздела.

После правок сверь статусы формализации в `question.md`, `context.md`, `review.tex`,
`blueprint.md`, `README.md`. Расхождение с `exposition.tex` назови в отчёте.

## 7. Проверки и отчёт

1. `scripts/check.ps1`, `git diff --check`.
2. Отчёт пользователю, по порядку:
   - что доказано сегодня (имена теорем, модуль) и какие узлы закрыты;
   - новые и отвергнутые идеи — по одной строке, с номерами из `ideas.md`;
   - пройденные проверки и те, что не запускались;
   - Aristotle: что принято, что отправлено сегодня (проект, цель), что ещё считается;
   - открытые узлы из `blueprint.md`;
   - решения за пользователем: новые определения, изменения постановки, коммит.
