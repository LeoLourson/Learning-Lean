# Фасеты единиц

Шапка файла — единственный носитель состояния. Ни один производный файл не
содержит состояния по своему усмотрению: `index.md`, `blueprint.md`,
`paper/generated/status.tex`, `output/generated/Axioms.lean` собираются из этих
шапок (`tools/state/`). Поэтому расхождение статусов между документами
невозможно: его негде записать.

Общие правила:

- Идентификаторы без ведущих нулей, сквозные внутри класса, только дописываются.
  `C1…C19`, `I1…`, `S1…`, `A1…`, `E1…`, `Q` для постановки.
- Имя файла: `<id>-<slug>.md`, где `slug` — короткая латиница с дефисами.
  Идентификатор в шапке совпадает с префиксом имени файла.
- Ссылки в текстах — по идентификатору (`C7`), не по `файл:строка`.
- Даты — ISO `YYYY-MM-DD`. Порядок сортировки в сводках числовой.
- Шапка — плоский YAML из скаляров и списков в квадратных скобках; никаких
  вложенных словарей, многострочных блоков и якорей.

Канонические ключи статуса записи (соответствие прежним словам проекта):

| Ключ | Прежнее слово |
| --- | --- |
| `unverified-source` | непроверенный источник |
| `own-result` | собственный расчёт |
| `goal` | цель исследования |
| `proved-lean` | лемма, доказанная в Lean |
| `proved-aristotle` | принятый ответ Aristotle |

## `record` — `claims/C*.md`

```yaml
---
id: C7
title: Оценка резольвенты
status: proved-lean
depends_on: [C5, S4]
lean_theorem: Involution.resolvent_ray_estimate
final: true
checked_by: referee 2026-10-13
---
```

Обязательны: `id`, `title`, `status`, `depends_on` (список идентификаторов,
может быть пустым). `lean_theorem` обязателен при `status` = `proved-lean` или
`proved-aristotle`: полное имя объявления, а не имя файла (имена объявлений
перенос файлов не меняет). `final: true` — итоговая теорема проекта; из таких
записей собирается реестр аксиом. `checked_by` — независимая проверка:
`роль ГГГГ-ММ-ДД`, а при нескольких проверках список
`[роль ГГГГ-ММ-ДД, роль ГГГГ-ММ-ДД]` (рецензент, проверка соответствия
формализации, сверка с PDF идут разными ролями). Роль не проверяет собственную
работу; если проверок не было, поле отсутствует.

Тело записи сохраняется целиком, включая абзацы «Lean», «Границы»,
«Рецензия», «Соответствие формализации». Если в теле прозвучал статус, шапка
первична, а расхождение с телом — ошибка, которую правит автор записи.

## `idea` — `claims/I*.md`

```yaml
---
id: I22
title: Блочная редукция через жордановы цепочки
status: open
next: Проверить диагональность на векторе u = (1-x^2) η₁
---
```

Обязательны: `id`, `title`, `status` ∈ `open` | `rejected` | `promoted`,
`next` (следующий шаг; для отвергнутой — причина отказа). `promoted_to`
указывает запись, в которую идея перешла. Отвергнутые идеи не удаляются.

## `card` — `claims/S*.md`

```yaml
---
id: S4
title: Markus–Matsaev, теорема 2.1
status: verified
source: S4, теорема 2.1, с. 5
applies_to: [C12, C15]
checked_by: source-verifier 2026-10-13
---
```

Обязательны: `id`, `title`, `status` ∈ `unverified-source` | `verified`,
`source` (код, номер утверждения, страница), `applies_to` (список записей или
узлов, где результат применён; может быть пустым). Страница — страница PDF,
если не указана журнальная. Карточка описывает чужую теорему: доказательства
проекта живут в записях `claims/C*.md`, полные тексты и контрольные суммы — в
`sources/registry.json` и `output/literature/`. Карточка — наше утверждение
о чужом результате, поэтому лежит среди наших утверждений, а не в `sources/`.
Если заголовок в старом файле объединял два кода, карточки разделяются, а
неразделимая часть остаётся в первой со ссылкой из второй.

## `statement` — `claims/question.md`

```yaml
---
id: Q
title: Спектральная задача с отражением аргумента
---
```

Постановка одна. Её изменения датируются в теле, а не в шапке.

## `task` — `tasks/A*/request.md`

```yaml
---
id: A4
title: Первая цель формализации
status: sent
goal: Q
date: 2026-10-10
archive: output/snapshot
---
```

Обязательны: `id`, `title`, `status` ∈ `open` | `sent` | `answered` |
`accepted`; `goal` — идентификатор утверждения или постановки. Рядом лежат
`answer/` (что вернул внешний сервис) и `report.md` (что и куда перенесено,
какие объявления сверены, что дал `#print axioms`).

## `experiment` — `experiments/E*/README.md`

```yaml
---
id: E1
title: Численная проверка отделённости
node: I12
status: done
---
```

`node` — идентификатор идеи или записи, которую опыт проверяет.

## Проверка

`tools/check/structure.py` проверяет: наличие обязательных фасетов, совпадение
`id` с префиксом имени файла, уникальность идентификаторов, разрешимость
`depends_on`/`applies_to`/`goal`, ацикличность `depends_on`, наличие
`lean_theorem` там, где он обязателен, и то, что производные файлы
воспроизводимы байт в байт.
