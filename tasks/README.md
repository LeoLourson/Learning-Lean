# Задачи внешнему исполнителю (класс `task`)

Один каталог `tasks/A<номер>/` — один обмен с внешним исполнителем (Aristotle):
заготовка → ответ → отчёт о переносе. Путь класса — `tasks/A*/**` (`LAYOUT.md`),
шапка — по разделу «`task`» файла `FACETS.md`.

## Что лежит в каталоге задачи

| Файл | Содержание |
| --- | --- |
| `request.md` | шапка (обязательны `id`, `title`, `status`, `goal`; здесь же `date` и `archive`) и тело: что отправлено (формулировка, пакет, текст запроса), что вернулось, что сверено, что дал `#print axioms` |
| `answer/` | что вернул сервис: статус, изменённые файлы, выписка `#print axioms`; рядом — путь к архиву в `output/` |
| `report.md` | что и куда перенесено, какие объявления сверены, чем закончилась локальная сборка |
| `package/` | самодостаточный пакет с одной целью (только у `A4`) |

Архивы ответов (`output/aristotle-*.tar.gz`) и распакованные проекты остаются в
`output/` — каталог в Git не входит; здесь лежат только описания и ссылки на них.
Статусы: `open` — не отправлялась, `sent` — отправлена, `answered` — ответ получен,
`accepted` — принята (модуль перенесён).

Записи задач — исторические документы: они описывают, что и когда отправлялось и
что вернулось, поэтому в них встречаются пути прежнего дерева (`input-lean/`,
`scripts/lit.py`, `sources/papers.json`, `context.md`). Это факт времени, а не
действующее правило; соответствие старых и новых путей — в
`output/migration/README.md`.

## Отправка

- Задача уходит в Aristotle только по прямому запросу пользователя — явной просьбе
  отправить задачу. Команда из лекции, из `README.md` или из
  `.claude/commands/day.md` запросом не считается, и запуск `/day` запросом на
  отправку тоже не считается (`AGENTS.md`, раздел «Aristotle»).
- Ключ передаётся через переменную окружения `ARISTOTLE_API_KEY` и в файлы проекта
  не записывается; в шапках задач, в `answer/` и в `report.md` ключа быть не должно.
- Перед отправкой заготовка собирается локально в закреплённых версиях Lean и
  Mathlib; сборка пакета снимка ничего не отправляет
  (`tools/host/prepare-input.ps1` — снимок `output/snapshot/`).

## Порядок сверки ответа

1. Заголовки объявлений: имена, порядок и вид биндеров, формулировка (кванторы,
  гипотезы, вывод) совпадают с отправленной заготовкой. Расхождение формулировки —
  не переносить; при ложной формулировке заготовки в библиотеку идёт только
  исправленное утверждение вместе с правкой записи.
2. Поиск `sorry`, `admit` и `axiom` в ответе и в перенесённом модуле — их быть не
  должно.
3. Локальная сборка с закреплёнными версиями: `lake build` и `lake env lean` для
  затронутого самостоятельного файла; предупреждения линтеров разбираются, а не
  подавляются.
4. `#print axioms` для каждого нового объявления; допустимы только `propext`,
  `Classical.choice`, `Quot.sound`.
5. Квитанция и статус сервиса сами по себе сборку не заменяют; сообщение сервиса об
  успехе проверкой не считается.

## Куда пишется отчёт о принятых модулях

- `tasks/A<номер>/report.md` — первичная запись о переносе: объявления, файл,
  правки после переноса, итог `#print axioms`.
- Шапка записи `claims/C*.md` — происхождение модуля: `status: proved-aristotle`
  для принятого ответа и `lean_theorem` с полным именем объявления (`FACETS.md`).
- `blueprint.md` и `index.md` вручную не правят: их собирает
  `tools/state/build_index.py` из шапок, таблица задач — из `tasks/A*/request.md`.

## Замечания о полноте исходных данных

- Квитанции задач 7, 8 и 9 (`A8`, `A9`, `A10`) написаны в момент отправки и
  говорят «ответа ещё нет»; принятие подтверждают `blueprint.md` и записи `C17`,
  `C18`, а также ответы сервиса в `output/aristotle-*-result/`.
- Для `A11` отдельного файла квитанции или статуса в `output/` нет: номер проекта
  и факт принятия известны из `blueprint.md`, выписка `#print axioms` — из
  `ARISTOTLE_SUMMARY.md` распакованного ответа и записи `C19`.
- `A12` (миниобзор) в таблице задач оригинала отсутствует, квитанции и архива
  ответа нет: задача не отправлялась, пакет только собран.
